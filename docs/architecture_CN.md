# 架构

[English](architecture.md) · [规则参考](rules_CN.md)

go-inject 是源码变换与构建工具，对外提供 import 选择、Go 模板行为和可查看的生成源码。可观测 Agent、追踪上下文、采样和 exporter 不属于工具实现范围。

## 管线和职责

公开入口改为原生 Go 命令：`go build -toolexec="go-inject"`（以及 `go test`）和用于 vendor 生成的 `go generate`。编译代理自行识别父 Go 调用并启动本地会话。登记文件使用 `//go:build goinject || generate`，业务编译不启用登记标签。

这替代 beta.1 的顶层构建器。同一次原生 Go 调用会共享依赖编译动作：多个入口要求共享包生成不同源码时明确报错，要求分别构建；一致的结果共享编译。vendor 状态必须能随仓库迁移，完整校验与首次目录交付必须纳入同一事务边界。

```text
Go 命令参数及入口
        ↓
项目和业务依赖加载
        ↓
静态登记 imports → 规则包和版本变体
        ↓
目标绑定、校验、排序、依赖规划
        ↓
共享源码改写器
        ↓
构建会话 / vendor 事务
        ↓
实际命中、生成源码、诊断
```

| 职责 | 负责 | 不负责 |
|---|---|---|
| CLI | 命令、参数、退出状态和用户诊断 | 解释模板 |
| 项目加载 | Go 环境、包、模块、构建约束 | 目标库业务行为 |
| 规则加载 | 静态 imports、聚合、身份、变体 | 执行规则 init |
| 计划和校验 | 适用目标、签名、投影、冲突、依赖 | 文件写入提交 |
| 改写器 | 符号绑定、源码修改、imports、位置 | 执行 Go 命令 |
| 构建后端 | 隔离生成输入、编译及链接依赖闭包 | vendor 文件归属 |
| vendor 后端 | 原始状态、锁、冲突检查、恢复 | 修改标准库 |
| 报告 | 实际操作的证据 | 独立计算的预览实现 |

采用小型管线阶段和后端 Adapter，不引入服务容器、反射注册表或逐类型工厂。解析和加载复用标准 Go AST/类型工具、保留装饰信息的语法树，以及 Go 包和模块工具。

## 两张依赖图

**业务依赖图**来自未启用登记文件的应用入口，用于判断目标是否适用。模板为了签名而 import Gin，不应使 Gin 自动成为业务依赖。

**生成后的构建依赖图**包含实际生成源码和初始化需要的 imports，必须保证编译与链接输入完整、初始化有效、没有依赖循环。Go 已安排构建后再插入源码，不能被简化为向 `importcfg` 追加一行。

规则选择属于入口。不同 Go 调用隔离各入口的规则；同一次原生调用中，共享包结果不一致时明确报错。一份物理 vendor 只有一种结果，因此同样拒绝不兼容的入口结果。

## 源码语义

模板绑定真实目标声明，按角色映射接收者、参数和返回值名字。类型匹配保留包身份和完整类型结构。投影验证目标所需成员，显式新增操作增加目标局部声明或字段。

改写保留控制流、编译指令和诊断源码信息，不给原函数增加包装闭包。模板局部变量和新增声明需要稳定的符号归属。末尾顶层 return 按语法结构移除，分支及闭包中的 return 保持含义。

顺序属于计划，不由反复前置插入决定。同 order 使用稳定身份排序，重复导入去重，不兼容的新增声明报错。

## 状态和依赖

目标局部 helper 可以访问目标私有声明。共享 runtime 包应具有清楚且尽量小的依赖面，避免依赖被它拦截的使用方。把包局部状态复制到多个目标不会得到共享状态。

底层链接桥接必须验证签名、链接闭包和初始化，编译 hook 不会取消 Go 的类型规则。runtime 结构修改和标准库 hook 需要专门验证工具链，普通库示例不能代替这类测试。

## 可复现性和文件归属

构建会话记录规则选择、模块和工具链输入、目标源码、生成文件及结果。影响行为的输入变化时缓存身份必须变化；热缓存测试需只改规则并验证新二进制行为。并行会话不能共享可变的构建路径记录。

vendor 生成是针对明确归属文件的事务。保存原始内容，检查用户编辑和旧产物，再按记录恢复。锁和恢复记录处理操作中断。第二次成功执行不能在自己的产物上再叠加一次注入。

## 参考实现

- [go-build-hijacking](https://github.com/0x2E/go-build-hijacking)：编译输入替换和 import 配置。
- [SkyWalking Go](https://github.com/apache/skywalking-go)：方法与结构体增强、runtime 桥接和入口初始化；其 Agent 运行时不属于本工具范围。
- [Orchestrion](https://github.com/DataDog/orchestrion)：通过 import 选择规则、新增依赖和构建集成。
- [Garble](https://github.com/burrowers/garble)：Go 构建驱动、与变换输入关联的缓存身份和编译器委托。

这些经验用于确定职责边界，不要求暴露相同的插件开发 API。本实现按[测试契约](testing_CN.md)验收。
